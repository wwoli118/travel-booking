# 여행 예약 자동화 (회사 출장용)

원칙은 [CLAUDE.md](CLAUDE.md)를 따릅니다. 결제·주문 생성은 하지 않으며, 현재는 **Duffel 테스트(샌드박스) 키로 편도 항공권 검색 → 예약 전 확인 요약 → 주문 준비(결제 없는 보류 주문) → 회계용 예약 내역 기록**까지 합니다.

## 설치

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env   # 그리고 DUFFEL_API_KEY=duffel_test_... 입력
```

`duffel_test_`로 시작하지 않는 키는 API를 호출하기 전에 거부됩니다.

## 항공권 검색 (편도, 가격순)

```bash
python -m src.flights --from ICN --to MNL --date 2026-12-20 --adults 2
```

| 옵션 | 설명 |
|---|---|
| `--from`, `--to` | 공항 IATA 코드 (3글자) |
| `--date` | 출발일 `YYYY-MM-DD` (오늘 이후) |
| `--adults` | 성인 인원 1~9 (기본 1) |
| `--cabin` | `economy`(기본) / `premium_economy` / `business` / `first` |
| `--limit` | 화면 표시 건수 (기본 20, CSV에는 전체 저장) |

결과: 항공사, 편명, 출발/도착 현지 시각, 경유 수, 총액+통화를 가격순으로 출력하고
`data/flights_<출발>-<도착>_<출발일>_<조회시각>.csv`에 저장합니다 (엑셀 호환 UTF-8 BOM).

- 같은 가격이면 출발 시각이 이른 순으로 정렬합니다.
- 결과에 통화가 섞여 있으면 환율 없이 비교할 수 없으므로 정렬하지 않고 오류를 냅니다.
- 해석할 수 없는 운임은 버리지 않고 제외 사유를 경고로 출력합니다.
- 샌드박스 결과는 실제 운항·가격이 아닌 테스트 데이터입니다.

## 예약 전 확인 요약

검색 결과에서 고른 항공편을 Duffel에 다시 조회해서, 탑승객 정보와 함께 요약을 보여주고 `yes/no` 확인을 받습니다.
**주문 생성과 결제는 하지 않습니다.**

1. 탑승객 파일 작성 (개인정보이므로 `data/` 아래에 두며 git에 올라가지 않습니다)

   ```bash
   cp travelers.example.json data/travelers.json
   ```

   - 이름: 여권 영문 표기 그대로 (A–Z, 공백, 하이픈). 소문자로 써도 대문자로 바뀝니다.
   - 호칭 `mr/ms/mrs/miss/dr`, 성별 `m/f`, 생년월일 `YYYY-MM-DD`
   - 전화번호: 국가번호 포함 (`+821012345678`)
   - `trip.purpose`(출장 목적), `trip.cost_center`(비용 부서)는 선택 항목입니다.
   - `passport`(여권번호·만료일·발급국 2글자 코드)는 선택 항목입니다. 운임이 여권 정보를 요구하면 필수로 검사하고,
     출발일 전에 만료되면 막고, 출발일 기준 잔여 6개월 미만이면 경고합니다. 화면에는 번호 일부만 보여줍니다.
   - 탑승객 수는 검색 인원과 같아야 하고, 출발일 기준 만 18세 이상이어야 합니다.

2. 실행

   ```bash
   python -m src.summary --csv data/flights_ICN-MNL_2026-12-20_<조회시각>.csv --rank 1
   ```

   `--offer off_...`로 운임 ID를 직접 넣을 수도 있습니다. `--travelers`로 다른 탑승객 파일을 지정할 수 있습니다.

요약 항목: 항공편·경유지, 구간과 현지 시각, 좌석 수와 등급, 탑승객 영문 이름, 총액(검색 시 가격과 비교),
출발 전 환불·변경 규정, 수하물, 운임 유효 시각, 출장 목적/비용 부서.

- 가격이 오르거나 통화가 바뀌면 경고를 표시합니다.
- 운임 유효 시간이 지났으면 확인을 받지 않고 중단합니다. 다시 검색하세요.
- `yes`일 때만 `data/drafts/draft_<구간>_<출발일>_<확인시각>.json`에 예약 준비 내용을 저장합니다.
  탑승객은 Duffel 승객 ID와 순서대로 짝지어 저장되어 다음 단계(주문 준비)에서 씁니다.

## 주문 준비 (결제 직전까지)

Duffel의 즉시 발권(instant) 주문은 결제를 포함하므로 **만들지 않습니다**. 결제 API는 코드에서 호출 자체를 차단합니다.
대신 결제 없이 좌석·가격을 잡아두는 **보류(hold) 주문**까지만 하고, 결제는 사람이 Duffel 대시보드에서 직접 합니다.

```bash
python -m src.orders prepare            # 점검 모드: 주문 요청서만 저장 (API로 주문하지 않음)
python -m src.orders prepare --hold     # 최종 요약 + yes 확인 후 샌드박스 보류 주문 생성
```

- `--draft data/drafts/draft_....json`으로 준비 내용을 지정할 수 있습니다. 생략하면 가장 최근 것을 씁니다.
- 운임을 다시 조회해 2단계 확인 때와 가격을 비교하고, 결제 마감·가격 보장 시각을 보여줍니다.
- 다음 경우에는 주문을 만들지 않고 중단합니다:
  운임 유효 시간 만료 / 즉시 결제가 필요한 운임(보류 불가, 정보가 없을 때도 보류 불가로 판단) /
  승객 구성 변경 / 여권 정보 누락·만료 / 운영(live) 운임.
- 여권 정보는 운임이 요구할 때만 Duffel에 보냅니다.
- 결과는 `data/orders/`에 저장됩니다: 요청서 `order_request_*.json`, 보류 주문 `order_<예약번호>_*.json`.
- 보류 주문은 결제 마감까지 결제하지 않으면 자동 취소됩니다.

### 보류 주문 취소

```bash
python -m src.orders cancel --order ord_0000...
```

취소 견적(환불액)을 먼저 보여주고 `yes` 확인 후에만 취소를 확정합니다.

## 회계용 예약 내역

`data/ledger.csv`에 주문 1건당 1행으로 기록합니다 (엑셀에서 바로 열리는 UTF-8 BOM, 한글 열 이름).
git에는 올라가지 않습니다.

| 시점 | 내역 변화 |
|---|---|
| 보류 주문 생성 (`orders prepare --hold`) | 자동 추가, 상태 `결제대기`, 영수증 `N` |
| 보류 주문 취소 (`orders cancel`) | 자동 갱신, 상태 `취소`, 환불액·환불통화 기록 |
| 사람이 Duffel 대시보드에서 결제한 뒤 | `sync`로 Duffel 주문 상태를 조회해 반영, 또는 `mark-paid`로 직접 표시 |

```bash
python -m src.ledger list                                  # 내역 + 상태·통화별 합계
python -m src.ledger sync                                  # 취소 외 전체 주문의 결제 여부를 Duffel에서 조회해 반영
python -m src.ledger sync --order ord_0000... --dry-run    # 특정 주문만, 내역은 바꾸지 않고 결과만 보기
python -m src.ledger mark-paid --order ord_0000... --receipt   # 결제완료 (영수증 받았으면 --receipt)
python -m src.ledger receipt --order ord_0000... --yes         # 영수증 여부만 변경 (--yes / --no)
```

- 열: 기록일시, 출발일, 구분, 출장자, 인원, 출장목적, 비용부서, 구간, 항공사, 편명, 예약번호, 주문ID,
  금액, 통화, 상태, 결제마감, 결제확인일시, 영수증, 환불액, 환불통화, 비고, 테스트(샌드박스 여부),
  항공권번호, 최종조회일시. (뒤의 두 열이 없는 예전 파일도 그대로 읽고, 다음 기록 때 열이 추가됩니다.)

### 결제 여부 조회 (`sync`)

Duffel 주문을 **조회만**(`GET /air/orders/{id}`) 해서 내역에 반영합니다. 결제는 하지 않습니다.

| Duffel 상태 | 내역 `결제대기` | 내역 `결제완료` | 내역 `취소` |
|---|---|---|---|
| 결제완료 | → `결제완료`, 결제확인일시·항공권번호 기록 | 유지 (빈 결제확인일시만 채움) | 유지 + 경고 |
| 결제대기 | 유지, 결제 마감 안내 (지났으면 경고) | 유지 + 경고 | 유지 + 경고 |
| 취소 | → `취소` | → `취소` + 환불 확인 경고 | 유지 |

- 내역과 Duffel이 어긋나면 덮어쓰지 않고 경고만 합니다. 사람이 확인 후 고치세요.
- Duffel이 결제 상태 정보를 주지 않으면 결제됐다고 가정하지 않고 조회 실패로 처리합니다.
- 금액·통화가 내역과 다르면 경고합니다.
- 조회에 실패한 주문은 원인을 출력하고 나머지는 계속 조회하며, 실패가 있으면 종료 코드 1입니다.
- 영수증 여부는 결제와 별개라 자동으로 바꾸지 않습니다.
- 합계는 통화별로만 냅니다 (환율 환산 없음).
- 결제완료인데 영수증이 없는 건은 `list`에서 경고합니다.
- `mark-paid`는 기록만 바꿉니다. 이 코드는 결제를 하지 않습니다.
- 엑셀에서 파일을 열어둔 채 기록하면 실패할 수 있습니다. 이때는 원인을 출력하며, 기존 내역은 손상되지 않습니다.

## 구조

```
src/config.py    .env 로드, 테스트 키 강제
src/models.py    검색 조건·항공편 모델 (pydantic, 금액은 Decimal)
src/duffel.py    Duffel API 공용 호출 (테스트 키 재확인, 결제 엔드포인트 차단, 오류 원인 출력)
src/flights.py   항공권 검색 + CLI
src/compare.py   가격순 정렬
src/export.py    검색 결과 CSV 저장
src/offers.py    운임 재조회 (가격·규정·만료·수하물), 검색 CSV에서 선택
src/travelers.py 탑승객 정보 검증 (여권 영문 이름, 나이, 연락처)
src/summary.py   예약 전 확인 요약 + yes/no + 준비 내용 저장
src/orders.py    주문 요청서 생성, 보류 주문 생성·취소 (결제 없음)
src/ledger.py    회계용 예약 내역 CSV (자동 기록, 결제 여부 조회·반영, 영수증 표시, 통화별 합계)
src/order_status.py  Duffel 주문 상태 조회 (결제·취소·항공권번호, GET 전용)
```
